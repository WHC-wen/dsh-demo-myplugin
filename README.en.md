# DSH Prompt Optimizer (`dsh-demo-myplugin`)

A prompt-optimization plugin for **DeepSeek Harness**: a persistent sparkle icon sits at the right end of the chat composer's tool row. Click it to read the current draft, improve it with either an **LLM polish** or a **rule-based rewrite**, preview the result in a floating panel, and replace the draft or cancel — without ever interrupting the typing flow.

This repository is a **formal Cordis plugin package (bundle)**: `dsh.bundle.patch` inserts one row into the composition layer, the host half registers a same-origin HTTP route through `webServer`, and the client half (Web platform) registers the composer entry. Once installed into a profile it loads automatically with DSH and survives restarts.

- **Zero dependencies**: `dependencies`, `devDependencies` and `peerDependencies` are all empty — no `npm install`, clone and build.
- **Artifacts are generated from source**: `lib/` is the build output of `src/` (`npm run build`) and `npm test` compares them byte for byte, so a hand edit to the artifact cannot survive.
- **Four independent verification layers**: `npm test`, `npm run guards`, and `npm run verify` (packed tarball / real composition layer / real profile loader), plus GitHub Actions running the same set on Linux and Windows.

## ✨ Features

- **Two optimization modes**
  - `智能优化` (auto): polishes the draft with the `llm` service using the model selected in the current session; a missing service, no selected model, a failing stream or a 45 s timeout all fall back to the rule engine automatically.
  - `快速重写` (rule): a built-in rule engine — zero API cost, instant. Structured bilingual rewrite (role / task / context / extracted constraints / output format). A draft of ≤8 characters, or one that is already structured, is returned untouched instead of being forced into a template.
- **Persistent entry + floating panel**: registered in the `conversation.input.right` slot (right end of the composer tool row, left of the model selector); the panel shows the preview, names the engine (`已由大模型润色` / `已由规则引擎重写`), and offers `替换原文` (writes the draft back atomically through `inputActions.setDraft`) and `取消`.
- **Theme and viewport aware**: colors come from DSH theme tokens (`--dsw-alias-*`); the panel is `max-height: min(420px, calc(100vh - 220px))` and scrolls internally in short windows.
- **State feedback**: spinner while optimizing, empty-draft hint, engine attribution, failure reason.

## 🚀 Install

Pick any one of the three routes. `dsh.profile.bundles` reconciles automatically afterwards; **restart `dsh web` to take effect**.

```sh
# 1) install straight from this directory (most convenient while developing)
dsh plugin --profile web add .

# 2) pack first, then install (required when the path contains spaces)
npm pack --pack-destination "$env:TEMP"
dsh plugin --profile web add "file:$env:TEMP/dsh-demo-myplugin-0.1.0.tgz"

# 3) install from GitHub (once the repository is published)
dsh plugin --profile web add github:WHC-wen/dsh-demo-myplugin
```

Confirm the composition layer picked it up:

```sh
dsh --profile web --dump-config | Select-String -Context 0,2 'dsh-demo-myplugin'
# expected:
#   # == dsh-demo-myplugin
#   - id: prompt-opt
#     name: dsh-demo-myplugin
```

Remove it:

```sh
dsh plugin --profile web remove dsh-demo-myplugin
```

> **Paths containing spaces**: `dsh plugin add` is a `pnpm add` forwarder, and a space inside a `file:` path gets truncated. Pack first with `npm pack`, then install `file:<absolute path to the tgz>` (route 2 above).
>
> **Relative specs resolve against the invoking directory**: the `.` in `dsh plugin add .` is rewritten relative to the directory you run the command from — use an absolute path when running it elsewhere.

## ⚙️ Configuration

The DSH-related fields in `package.json`:

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-runtime"], "external": [] }
}
```

- `dsh.bundle.patch`: declares this a bundle layer. `dsh plugin add` consults this single field to decide whether the package joins `dsh.profile.bundles`; a dependency without it only earns a warning.
- `dsh.client.platform`: the client half targets `web`.
- `dsh.client.inject`: module-graph dependency hints (platform package names). It names `@deepseek-ai/dsh-client-runtime` because that is the package implementing the `slots` service, and it is already a parser preload.
- `dsh.client.external`: empty. The only thing the client bundle `require`s is `react`, which is part of the shell baseline (supplied by the platform seed) and creates no module-graph edge.
- No environment variables or config files are needed.

`cordis.patch.yml`:

```yaml
- insert:
    - id: prompt-opt
      name: dsh-demo-myplugin
```

`id` is the plugin's identity inside the composition layer and `name` is the package to load — the two differing is intentional and is this plugin's existing convention.

## 🛠 How it works

**Host half** (`lib/index.js`, ESM): `name = "prompt-opt"`, `inject = ["webServer", "timer"]`; it registers a same-origin route inside `ctx.effect`:

```
POST /api/prompt-opt/optimize   { text, mode } -> { ok, text, engine }
```

- Request bodies are capped at 64 KiB — beyond that it answers 413 and drops the connection; a non-POST answers 405; an empty draft answers `ok: false` with a hint.
- `智能优化` calls `llm.stream` with the model from `agentDefaultModel.currentSelection()`, guarded by a 45 s timeout and output cleaning (code fences stripped). Any failure logs a warning and falls back to the rule engine, so the user always sees a 200.

**Client half** (`lib/client.js`, classic script): a hand-written `window.__ModuleLoader__.load` bundle whose module-table id equals the package name; `inject = ['slots']`; it registers the sparkle icon and floating panel into `conversation.input.right` as `id: prompt-opt`, `order: 20`; a click issues a same-origin `fetch('/api/prompt-opt/optimize')`, and `替换原文` writes back through `inputActions.setDraft`.

Both halves share exactly one thing: the path constant and request-body constructor in `src/endpoint.js`, so the host and the browser cannot each keep their own copy of the path — `npm run guards` checks this.

> Difference from the "dynamic Cordis plugin" version: that one used the in-package RPC of `harness.handle` + `host.call` and only lived for the session; this bundle version uses a `webServer` same-origin route plus `fetch`, so it persists with the profile. Do not enable both at once (they would register two entries in the same slot).

## 🧪 Development and verification

```sh
npm run build     # generate lib/ from src/ (the only writer of lib/)
npm test          # build --check + 18 behavioural tests
npm run guards    # packaging guards (deps, identity, manifest, freshness, route agreement)
npm run verify    # guards + packed tarball + real composition layer + real profile loader
```

What each layer can and cannot prove:

| Layer | Command | What it proves |
| --- | --- | --- |
| Behaviour tests | `npm test` | bundle registration shape, face, slot registration, request body, route behaviour, timeout fallback, 413/405 |
| Packaging guards | `npm run guards` | zero dependencies, package name = bundle id = patch `name`, the patch still declares the layer `id: prompt-opt`, every file the manifest promises exists, `lib/` is not behind `src/`, both halves agree on the path |
| Packed artifact | `verify-pack.mjs` | after unpacking the `npm pack` tarball: the bundle runs against a stub loader, the host imports over real ESM and answers one request |
| Real composition | `verify-dsh.mjs` | composes with DSH's own `ClientModuleRegistry`, extracts the `/plugins/<name>/client.js?rev=…` boot row, and confirms the served bytes equal the packaged bytes exactly |
| Real profile | `verify-profile.mjs` | composes an `id: prompt-opt` row through `@deepseek-ai/dsh-app-boot`'s `loadProfile` + `composeEntries` (in a temp DSH_HOME — your real profile is never touched) |

The last two print SKIP and exit 0 on a machine without DSH installed, so neither CI nor a fresh checkout can fail spuriously.

**Change loop**: edit `src/` → `npm run build` → `npm test` → `npm run verify` → commit and push. `lib/` is an artifact but **must be committed**: a GitHub install never runs the build.

## 🔄 CI and publishing

`.github/workflows/ci.yml` runs on every push to `main` and on every PR, across `ubuntu-latest` + `windows-latest` (Node 20): `npm run build` → `npm test` → `npm run guards` → `npm run verify`. There is no install step (zero dependencies), and the Windows job verifies that `.gitattributes` keeps LF after checkout — the tests compare bytes, so CRLF would fail immediately.

Pushing to your repository:

```sh
git remote -v                      # origin should point at your repository
git add -A
git commit -m "…"
git push -u origin main
```

> **If the repository already has older commits**: this package ships a rewritten history (3 commits: the formal package, a guard-hardening commit, and a publishing note) that shares no ancestor with the earlier dynamic-plugin commits, so `git push` is rejected. Either point it at an empty/new repository (plain `git push -u origin main` then succeeds), or overwrite the old one with `git push -u origin main --force`. To keep the old history instead, run `git pull --allow-unrelated-histories origin main` first, resolve, then push.

## ⚠️ Caveats and known limits

- Harness plugins are **trusted host code** running with the `dsh` process's privileges; review dependencies and install scripts, and try a throwaway profile first.
- LLM polishing consumes quota on whichever model API you configured; `快速重写` makes no call at all.
- When the `llm` / `agentDefaultModel` services are missing it degrades to the rule engine and keeps working.
- The rule engine returns drafts of ≤8 characters, or already-structured ones, untouched — by design, so a small prompt is not inflated into a template.
- The panel mounts in the `conversation.input.right` slot and overflows upward out of the composer; that slot's documented budget is one row tall and the composer card has no `overflow: hidden`, so it is not clipped — but in a very short window it can overlap the content above.
- `SYSTEM_PROMPT` in `src/optimizer.js` is a **reconstruction**: in the shipped artifact `llmRewrite` referenced a `SYSTEM_PROMPT` that was never declared (a runtime `ReferenceError`). This package supplies that Chinese system prompt, worded from the plugin's intent — it is not recovered text. If you still have the original sentence, replace that constant.
